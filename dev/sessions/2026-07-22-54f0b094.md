Here's what it means, in plain terms.

**A "fixture"** is just testing jargon for a fixed lump of test data stored in the repo — a set of inputs you feed to your function every time you run the tests.

**"Golden"** means that alongside those inputs you also store the answers you already know to be correct. The test then does one thing: run the function on the stored inputs, check it gives back the stored answers. If someone later changes the code and a number moves, the test fails and tells you. The word "golden" is just "this is the master copy, the answer of record" — like a golden master recording. It's standard vocabulary in software testing, but there's no reason you should have to know it.

So a golden fixture for the capacity equation would be, concretely: a small table of maybe a dozen rows. Each row has values for `m`, `a`, `p`, `c`, `nu` — and the value of `V` that those inputs *should* produce, worked out by a person with the equation and a calculator, or in a spreadsheet. That table gets committed. The test checks `capacity(m, a, p, c, nu)` reproduces the `V` column.

**Why this is a separate job from the other tests.** Most of the tests in #28 check *properties* rather than values: capacity is zero when abundance is zero, capacity doubles when abundance doubles, survival can't go up when killing goes up. Those are valuable, but a wrong equation can satisfy all of them. If I mistakenly wrote `a` where the equation says `a*`, or divided by `mu` where I should have divided by `-log(p)`, every one of those property tests still passes. Only a stored, independently-computed number catches it.

**And this is the part I was making a fuss about.** If I write the R function from the spec, and then I also produce the "known correct" table from the spec, and I misread the equation — I'll misread it the same way twice. The table will agree with the code perfectly, the test will pass, and it will have proved nothing. The number has to come from someone working from the equations who hasn't seen the code. Given that the equations in this repo have already been through a chain of Nick's handwriting → Copilot → an agent writing R, that's the one place a plausible-looking wrong answer could survive all the way into a published VCI map. Realistically that means you or your co-maintainer doing a dozen rows in a spreadsheet, once — not a big job, but not one an agent can do for you.
