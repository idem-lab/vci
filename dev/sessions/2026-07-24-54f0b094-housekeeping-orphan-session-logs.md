## Recommendation: preventing recurrence

**Root cause, in one line:** the hook writes a per-branch log *every turn*, but committing it is manual and bound to a feature branch's PR — so turns on `main` (merges, triage) and post-merge wrap-up turns have no PR to carry them, and strand silently.

The tempting fix — **have the hook auto-commit its own log** — I'd advise **against**: it would either commit directly to `main` (breaking your "never commit to main" rule) or create commits you didn't authorise, at awkward moments (mid-rebase, mid-review). It also can't help the genuinely-final turn of a branch's life.

**What I'd actually do — three small, low-risk pieces that make the existing model converge instead of leak:**

1. **A visible backstop in the hook.** The Stop hook already runs every turn with git access. Have it, after writing, check for `dev/sessions/*.md` that are untracked or belong to a *different* branch than the one checked out, and print a one-line warning into the session: `⚠ N orphaned session log(s) — run the sweep`. This turns silent stranding into a recurring, impossible-to-miss nudge. No auto-commit, no `main` commits.

2. **A one-command sweep helper** (`.claude/hooks/sweep-session-logs.sh` or a `dev/` script): stages and commits any outstanding `dev/sessions/` changes *on the current branch*, with a standard message. Makes acting on the warning trivial and consistent.

3. **A Definition-of-Done line in CLAUDE.md:** "`dev/sessions/` has no uncommitted changes before a session ends; run the sweep." Plus the existing habit that `main`-only turns (merges/triage) get swept into a periodic housekeeping PR — exactly like #57 — rather than being expected to ride a feature PR they don't belong to.

Net effect: the log still lands via reviewed PRs (nothing bypasses review), but nothing can strand unnoticed, because every turn either commits its log or shouts that one is outstanding.

This is a workflow/tooling change, so I'll leave it as a recommendation rather than build it unprompted. Want me to open an issue for it (and, if you like, implement it in the same pass)?
